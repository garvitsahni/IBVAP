# Phase 5 — Interfaces Design Specification

**Date:** 2026-09-11
**Status:** APPROVED
**Phase:** 5 — Interfaces
**Features:** Command Dashboard, Patrol Companion App, Explainable Alert Overlay, Adversarial Blind-Spot Mapping

---

## 1. Executive Summary

Phase 5 builds the human-facing interfaces for the IBVAP system: a **Command Dashboard** for operators and a **Patrol Companion App** for field personnel. It also adds **clip overlay rendering** (burning detection data into video clips) and **blind-spot mapping** (visualizing uncovered camera zones).

All interfaces consume the Phase 4 REST/SSE API surface — no direct database access. The dashboard is a React + Vite + TailwindCSS SPA served by the fusion server. The patrol app is a separate React app with a focused alert-only UI.

**Exit Criteria:** A non-technical person can open the dashboard, see live alerts with overlays, view a footprint chain, and see the blind-spot map — without needing anyone to explain the underlying pipeline.

## 3. New API Endpoints

All new endpoints added to the fusion server under `/api/v1/`.

### 3.1 Dashboard Stats
```
GET /api/v1/dashboard/stats
Response: { total_alerts_today, active_cameras, alerts_by_severity: {critical, high, medium, low}, active_watchlist_entries }
```

### 3.2 Time-Range Alert Filtering (Extension)
```
GET /api/v1/alerts?since=ISO8601&until=ISO8601&status=...&camera_id=...&object_id=...
Response: List[AlertResponse] (existing shape)
```

### 3.3 Camera Registry
```
GET /api/v1/cameras
Response: [{ camera_id, name, fov_polygon?, status, last_seen, health: {ssim, metric} }]
```

### 3.4 Ledger Global Status
```
GET /api/v1/ledger/status
Response: { is_valid, broken_at_index, total_entries, last_verified }
```

### 3.5 HLS Video Streams
```
GET /api/v1/streams/{camera_id}.m3u8          → HLS playlist
GET /api/v1/streams/{camera_id}/{segment}.ts  → MPEG-TS segment
```
Generated by FFmpeg RTSP → HLS transcoding running as subprocess on the fusion server.

### 3.6 Blind-Spot Map
```
GET /api/v1/coverage/blind-spots
Response: { camera_id: { fov_polygon, covered_union, blind_spots: [polygon...] } }
```

### 3.7 Clip Serving
```
GET /api/v1/clips/{filename}  → Static file serve from clip store directory
```

### 3.8 ROI Polygon Update (for drawing UI)
```
PUT /api/v1/rois/{roi_id}  (existing, supports polygon field)
```

## 4. Dashboard Architecture

### 4.1 Technology Stack
- **Framework:** React 18 + Vite 5 + TypeScript
- **Styling:** TailwindCSS 3 with custom design tokens
- **Video:** `hls.js` for HLS playback
- **SSE:** Native `EventSource` with custom reconnection hook
- **State:** React Context + hooks (no Redux)
- **Maps/Canvas:** HTML5 Canvas (no external mapping lib)

### 4.3 Design System Compliance
All components use DESIGN_SYSTEM.md tokens via Tailwind config:

| Token | Tailwind Class | Use |
|-------|----------------|-----|
| `--alert-critical` | `bg-alert-critical` | Critical alert cards |
| `--alert-standard` | `bg-alert-standard` | Standard alert cards |
| `--ai-enrichment` | `bg-ai-enrichment` | AI explanation sections |
| `--system-ok` | `bg-system-ok` | Healthy camera indicator |
| `--system-degraded` | `bg-system-degraded` | Degraded camera banner |
| `--system-compromised` | `bg-system-compromised` | Compromised camera/ledger |
| `--neutral-*` | `bg-neutral-*` | Backgrounds, text, chrome |

Typography: sans-serif for UI (Inter), monospace for data (ledger hashes, timestamps, coordinates).

### 4.4 Core Screens (per DESIGN_SYSTEM.md Section 4)

1. **Live Alert Queue** — Priority-ranked by threat score, critical pinned top. Cards show: camera ID, timestamp, deterministic reason, threat score, status badge.
2. **Alert Detail** — Click opens full record: overlay clip, footprint chain, AI enrichment (visually separated, muted blue/purple), ledger verification status.
3. **Footprint Chain Viewer** — Timeline/graph of camera hops with timestamps. Answers "where from, where to" at a glance.
4. **Camera Grid / Coverage Map** — Live feed thumbnails with health indicators. Blind-spot overlay: covered regions (green) vs. gaps (striped red).
5. **Ledger Status Panel** — Persistent indicator: chain verified / broken. If broken, shows broken entry and detection time.
6. **ROI Configuration UI** — Draw/edit polygons on camera view (click vertices, drag, double-click close).
7. **Searchable Event Log** — Filterable table of all detection events.

### 4.5 Interaction Rules (per DESIGN_SYSTEM.md Section 5)
- Critical alerts require explicit acknowledgment (click/tap) — creates audit trail.
- AI enrichment always appended below deterministic reason, never replaces it.

## 7. Blind-Spot Computation

### 7.1 Module
`fusion_server/services/coverage.py` (new)

### 7.2 Algorithm
```python
def compute_blind_spots(cameras: List[Dict], rois: List[ROI]) -> Dict:
    for each camera:
        1. Get FOV polygon (from camera config or default 60° cone)
        2. Get active ROIs for camera (camera_id match or "*")
        3. Union all ROI polygons → covered_region
        4. blind_spots = FOV.difference(covered_region)
        5. Return {camera_id: {fov, covered, blind_spots: [polygon...]}}
```

### 7.3 Coordinate System
All polygons in normalized 0-1 camera coordinates. Dashboard renders on Canvas/SVG in same space.

## 9. Video Pipeline: RTSP → HLS

### 9.1 Architecture
FFmpeg subprocess per camera, managed by fusion server:
```
RTSP (mediamtx) → FFmpeg (libx264, hls) → /tmp/hls/{camera_id}/*.m3u8 + *.ts → Served via FastAPI static files
```

### 9.2 FFmpeg Command (per camera)
```bash
ffmpeg -i rtsp://mediamtx:8554/{camera_id} \
  -c:v libx264 -preset ultrafast -tune zerolatency \
  -f hls -hls_time 2 -hls_list_size 5 -hls_flags delete_segments \
  /tmp/hls/{camera_id}/stream.m3u8
```

### 9.3 Endpoint
`GET /api/v1/streams/{camera_id}.m3u8` → serves the HLS playlist from `/tmp/hls/{camera_id}/`

## 14. Risks & Mitigations

| Risk | Mitigation |
|------|------------|
| FFmpeg CPU usage on laptop | `-preset ultrafast -tune zerolatency`; limit to 2 cameras in Stage 1 |
| SSE reconnection on network blip | Exponential backoff in `useSSE` hook; tests cover disconnect/reconnect |
| ROI drawing UX on mobile | Patrol app doesn't need it; dashboard is desktop-first |
| HLS latency (~6-10s) | Acceptable for dashboard; patrol app uses SSE alerts not video |
| Clip rendering blocking | Fire-and-forget background task; never blocks alert delivery |
